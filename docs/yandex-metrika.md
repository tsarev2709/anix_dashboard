# Яндекс Метрика: подключение счётчика 103290769

Раздел «Сайт и AI» читает статистику через защищённый `control-center`.
Существующая проверка сессии и роли выполняется до обращения к Яндексу.
OAuth-токен не попадает в браузер, API-ответ, GitHub или журналы.

## Однократное подключение

1. Создать приложение Yandex OAuth для доступа к API. Название: Anix Dashboard.
2. Выбрать только `metrika:read`. Получить токен под аккаунтом, имеющим доступ к счётчику 103290769.
3. В Supabase **проекта дашборда `uuywdscpywuoacbbjhhb`**, Edge Functions → Secrets, сохранить:
   - `YANDEX_METRIKA_TOKEN`: полученный токен;
   - `YANDEX_METRIKA_COUNTER_ID`: `103290769` (также используется по умолчанию).
4. Опубликовать изменения дашборда и `control-center` штатными workflows.
5. Войти в дашборд, открыть «Сайт и AI», нажать «Обновить».
6. Сравнить визиты и уникальных посетителей с Метрикой за последние 7 календарных дней, включая сегодня. Используется часовой пояс счётчика.

Документация: https://yandex.ru/dev/metrika/ru/intro/quick-start
API отчётов: https://yandex.com/dev/metrika/en/stat/openapi/data

## Поведение

- Период: `6daysAgo` — `today`, не обязательно совпадает с сохранённым представлением `period=week` в интерфейсе Яндекса.
- Источники: последний значимый переход (`ym:s:lastSignTrafficSource`), до 10 источников. Cross-device соответствие интерфейсу отдельно не проверено.
- Общие уникальные посетители берутся из totals, а не складываются по дням.
- Кеш успешного отчёта — 5 минут на экземпляр функции. Ошибки не кешируются; прежний отчёт при ошибке не выдаётся как актуальный.
- Таймаут каждого из трёх параллельных запросов — 10 секунд. Недоступность Яндекса не ломает остальные данные control-center.
- Цели и офлайн-конверсии в этом изменении не подключаются: сначала нужно проверить список целей и правила квалификации.
- Подключение дашборда само по себе не создаёт коннектор для чтения Метрики в любых новых чатах.
