# Anix Control

Anix Control расширяет существующий закрытый `anix_dashboard` и становится единым управляющим интерфейсом для сайта, Wiki, интеграций и операционных метрик.

## Что входит в первый релиз

- раздел «Контент» с черновиками, статусами и историей версий;
- раздел «Сайт и AI» с метриками заявок и AI-диалогов, когда таблицы доступны в этом Supabase-контуре;
- серверные feature flags;
- безопасная пауза и возобновление интеграций;
- журнал административных действий;
- роли `owner`, `admin`, `editor`, `analyst`, `viewer`;
- защищённая Edge Function `control-center`.

Текущая авторизация остаётся ограниченной владельцем `studio@anix-ai.pro`. Таблица ролей подготовлена для следующего этапа, но публичная регистрация не открывается.

## Граница первого релиза

Сохранение записи в разделе «Контент» создаёт управляемый черновик и версию в Supabase. Оно пока не изменяет файлы `anix_landing` или `anix_wiki` автоматически.

Автопубликация должна быть добавлена отдельным этапом:

1. администратор переводит материал в статус `review`;
2. серверная функция валидирует структуру;
3. публикационная функция создаёт commit или pull request в нужном репозитории;
4. существующий GitHub Actions собирает и публикует сайт;
5. результат и commit SHA записываются в журнал.

Feature flags в первом релизе также являются серверным control plane. Основной сайт начнёт учитывать их после подключения публичного read-only endpoint с кэшированием и статическим fallback.

## Безопасность

- браузер получает только Supabase publishable key и пользовательский JWT;
- service-role key используется только внутри Edge Function;
- токены внешних сервисов не возвращаются интерфейсу;
- все изменения пишутся в `admin_audit_log`;
- прямой доступ `anon` и `authenticated` к административным таблицам закрыт RLS;
- приостановленные amoCRM и YouGile синхронизации завершаются штатно с `skipped=true`.

## Таблицы

- `admin_profiles` — административная роль;
- `content_entries` — текущее состояние материала;
- `content_versions` — снимок каждой сохранённой версии;
- `feature_flags` — серверные переключатели функций;
- `admin_audit_log` — неизменяемый журнал действий;
- `data_sources.enabled` — разрешение на запуск синхронизации.

## API

### GET /functions/v1/control-center

Возвращает:

- роль текущего пользователя;
- список материалов;
- источники и их состояние;
- feature flags;
- агрегаты сайта и AI за 30 дней, если соответствующие таблицы доступны.

### POST /functions/v1/control-center

Действия:

- `save_content`;
- `set_source_enabled`;
- `set_feature_flag`.

Каждое действие повторно проверяет роль на сервере.
