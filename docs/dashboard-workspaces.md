# Управленческий дашборд: разделы и достоверность

Обновление 24.09.2026. Главная — четыре направления, пять приоритетных исключений, краткие показатели и раскрываемый недельный обзор. Детальные отчёты перенесены в свои разделы, их прежние DOM ID и механизмы обновления сохранены.

## Продажи

Вкладки: действия сотрудников; результаты и воронка; прогноз; пирамида метрик.

Журнал `sales-activity` читает всю сохранённую историю с keyset-пагинацией. Автор — `created_by`, без подмены текущим ответственным. Время и календарные периоды — Europe/Moscow; неделя начинается в понедельник. Фильтры: сотрудник, период до 366 дней, тип, текущая воронка, поиск, входящие / системные записи. Пагинация интерфейса — 100 строк, CSV включает весь отфильтрованный результат. CSV экранирует формулы. Доступ проверяется по пользовательской сессии и профилю администратора.

Операция — событие CRM. Подтверждённое исходящее касание — outgoing_call/mail/chat_message/sms. Входящие, роботы и неизвестный автор отдельно. Одно действие может создать несколько разных событий CRM; число операций не равно числу осмысленных касаний, рабочему времени или продуктивности. Повторы одного исходящего подтверждения объединяются по его ID. Создание задачи и её завершение — самостоятельные операции; текст «позвонить» не считается доказательством звонка.

Для исследований используются явные теги завершённой задачи: `[Поиск контакта]`, `[Анализ компании]`, `[Анализ сегмента]`, `[Аналитика]`, `[Удаление дубля]`. Это самоотчёт, не автоматически наблюдаемая работа вне CRM. Если текст изменён после завершения, историческое событие не переклассифицируется. `entity_merged` означает объединение; обычное удаление не называется дублем.

Связь с воронкой — текущая связь сделки. Непривязанные контакты и компании видны без фильтра воронки. Удалённая карточка может не открыться в CRM, её событие остаётся в журнале. Настройки интеграций могут приписывать автоматические операции пользователю; требуется сверка авторства с CRM.

## Загрузка истории

Синхронизация больше не ограничивает события сделками и задачами. Читаются также контакты, компании и другие типы API. Последняя история обновляется с перекрытием двух дней; прежняя история восстанавливается недельными окнами от новых дат к старым, до 180 дней назад. Checkpoint хранится в закрытой `crm_activity_sync_state`. Частичная или неудачная выгрузка не продвигает checkpoint. Повтор безопасен за счёт upsert по ID события. При достижении лимита API синхронизация завершается ошибкой, а не выдаёт полную историю.

До завершения backfill журнал показывает дату, с которой загружены все доступные типы. Это полнота выгрузки API с правами текущей интеграции, а не доказательство полноты телефонии, почты и другой работы. Нет события ≠ не было работы.

## Исправление возраста сделок

`daysSince` получал число миллисекунд, превращал его в строку и разбирал через Date. Невалидная дата превращалась в 0. Поэтому возраст считался с эпохи Unix (~20 720 дней). Общий нормализатор принимает секунды, миллисекунды, числовые строки и ISO. Неизвестная дата возвращает null. CEO-срез также переведён на полную постраничную выборку CRM и YouGile, исключая скрытое ограничение PostgREST.

## Маркетинг

Метрика: 7 / 30 / 90 дней, сводные значения, дни, источники, входные страницы (топ-50), устройства, UTM source/campaign/content (топ-50), первые 20 целей, сравнение предыдущего периода. Частичные ошибки дополнительных отчётов не скрывают доступную сводку. Выборка и ограничения отображаются. Данные кэшируются на 5 минут по счётчику, периоду и детализации; токен не выдаётся клиенту.

Рекомендации — явные эвристики: страница с >=30 визитами и >=40% отказов; мобильные отказы выше desktop на >=15 п.п. при >=30 визитах обоих сегментов; нет целей; неполные UTM. Они не являются доказательством причины. Достижения разных целей не соединяются в фиктивную последовательную воронку. Нужны составные цели для точного оттока между CTA, формой и успешной отправкой.

Нативная аналитика Telegram и VK пока не подключена. UI разделяет переходы из соцсетей на сайт и отсутствующие охваты, подписки, реакции площадок. Для активации нужны идентификаторы канала/сообщества и авторизованный источник статистики. Секреты — только серверные. Разметка: source=telegram/vk, medium=social, campaign=кампания, content=пост.

## Пирамиды

- Продажи: операции и касания → качество / скорость → договоры × чек → выручка и маржа.
- Маркетинг: публикации / охват → переходы / конверсия → квалифицированные заявки / CPL → прибыль привлечённых клиентов.
- Производство: поток / блокировки → качество и переделки → принятый выпуск в срок → маржа проектов.
- Бизнес-модель: эксперименты → портфель / повторные продажи → юнит-экономика → прибыль и денежный запас.

Пока нет источников расходов, оплаты, трудозатрат и приёмки, соответствующие показатели не рассчитываются и не подменяются нулями. Существующие данные YouGile и CRM сохранены.

## Проверка

`node --test tests/*.test.mjs` — расчётные и интеграционные тесты модулей. `node --check` для клиентских файлов. DOM-проверка: сохранность ID старых отчётов, отсутствие дубликатов, переходы четырёх направлений. Проверка production-цифр требует авторизованной сессии владельца; экран входа не является проверкой цифр.
